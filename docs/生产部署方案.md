# VidForge 生产环境部署方案

本文档提供完整的部署流程，将 VidForge 部署为真实可访问的网站。

---

## 一、部署架构概览

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户访问层                                │
│                    https://your-domain.com                      │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                      前端静态资源                                │
│              Vercel / Cloudflare Pages (免费)                   │
│                    React + Vite 构建                            │
└─────────────────────────────────────────────────────────────────┘
                              │ API 请求
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                      后端 API 服务                               │
│              Railway / Render (约 $5-10/月)                     │
│                    NestJS + BullMQ                              │
└─────────────────────────────────────────────────────────────────┘
          │                    │                    │
          ▼                    ▼                    ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  PostgreSQL  │    │    Redis     │    │  对象存储     │
│  Railway/    │    │  Railway/    │    │  阿里云 OSS  │
│  Render      │    │  Render      │    │  或火山引擎   │
└──────────────┘    └──────────────┘    └──────────────┘
```

## 三、部署前准备清单

### 3.1 必需的外部服务账号

| 服务 | 用途 | 注册地址 |
|------|------|----------|
| GitHub | 代码托管 | https://github.com |
| 火山引擎 | AI视频生成、TTS | https://console.volcengine.com |
| 阿里云/火山引擎 | 对象存储 OSS | 同上 |
| Railway/Render | 应用托管 | https://railway.app 或 https://render.com |

### 3.2 敏感配置项清单

| 配置项 | 说明 | 获取方式 |
|--------|------|----------|
| `VOLC_ENGINE_ACCESS_KEY` | 火山引擎访问密钥 | 火山引擎控制台 → 访问控制 → 密钥管理 |
| `VOLC_ENGINE_SECRET_KEY` | 火山引擎密钥 | 同上 |
| `OSS_ACCESS_KEY` | OSS 访问密钥 | 阿里云/火山引擎控制台 |
| `OSS_SECRET_KEY` | OSS 密钥 | 同上 |
| `OSS_BUCKET` | 存储桶名称 | 创建存储桶时设置 |
| `OSS_ENDPOINT` | 存储桶端点 | 创建后自动分配 |
| `JWT_SECRET` | JWT 加密密钥 | 自行生成（见下方） |

**生成 JWT_SECRET：**
```bash
# 在本地执行
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```

## 四、详细部署步骤

### 步骤 1：准备火山引擎服务

#### 1.1 注册并实名认证
1. 访问 https://console.volcengine.com
2. 完成账号注册和实名认证
3. 充值至少 ¥100（按量付费）

#### 1.2 创建访问密钥
1. 进入「访问控制」→「密钥管理」
2. 创建新密钥，记录 `AccessKeyID` 和 `SecretAccessKey`
3. **重要**：密钥只显示一次，务必保存

#### 1.3 开通所需服务
- 智能创作服务（视频生成）
- 语音技术服务（TTS）
- 对象存储 TOS（或使用阿里云 OSS）

#### 1.4 创建对象存储桶
1. 进入对象存储控制台
2. 创建存储桶，选择「标准存储」
3. 设置权限为「公共读，私有写」
4. 记录 Bucket 名称和 Endpoint

---

### 步骤 2：部署后端到 Railway

#### 2.1 注册 Railway
1. 访问 https://railway.app
2. 使用 GitHub 账号登录
3. 验证邮箱

#### 2.2 创建 PostgreSQL 数据库
1. 点击「New Project」
2. 选择「Provision PostgreSQL」
3. 记录生成的 `DATABASE_URL`

#### 2.3 创建 Redis 实例
1. 在项目中点击「Add Service」
2. 选择「Provision Redis」
3. 记录生成的 `REDIS_URL`

#### 2.4 部署后端服务
1. 点击「Add Service」→「GitHub Repo」
2. 选择 `WANGLEVY9/VidForge` 仓库
3. 配置构建设置：

```
Root Directory: apps/backend
Build Command: npm install && npm run build
Start Command: npm run start:prod
```

#### 2.5 配置环境变量
在 Railway 后端服务的「Variables」面板中添加：

```env
# 数据库（Railway 自动注入）
# DATABASE_URL=已自动设置
# REDIS_URL=已自动设置

# JWT 配置
JWT_SECRET=<你生成的64位随机字符串>
JWT_EXPIRES_IN=7d

# 火山引擎配置
VOLC_ENGINE_ACCESS_KEY=<你的AccessKey>
VOLC_ENGINE_SECRET_KEY=<你的SecretKey>
VOLC_ENGINE_REGION=cn-beijing

# OSS 配置
OSS_ACCESS_KEY=<OSS访问密钥>
OSS_SECRET_KEY=<OSS密钥>
OSS_BUCKET=<存储桶名称>
OSS_ENDPOINT=<存储桶端点>

# 服务地址（部署后更新）
API_BASE_URL=https://<你的后端域名>
WEB_BASE_URL=https://<你的前端域名>

# 环境
NODE_ENV=production
```

#### 2.6 获取后端 URL
1. 在服务设置中添加自定义域名或使用默认域名
2. 记录后端访问 URL，如：`https://vidforge-api.railway.app`

---

### 步骤 3：部署前端到 Vercel

#### 3.1 注册 Vercel
1. 访问 https://vercel.com
2. 使用 GitHub 账号登录

#### 3.2 导入项目
1. 点击「Add New」→「Project」
2. 选择 `WANGLEVY9/VidForge` 仓库
3. 配置项目：

```
Framework Preset: Vite
Root Directory: apps/frontend
Build Command: npm run build
Output Directory: apps/frontend/dist
Install Command: npm install
```

#### 3.3 配置环境变量
在「Environment Variables」中添加：

```env
VITE_API_BASE_URL=https://<你的后端域名>
```

> 配置后必须确认该后端域名已经在 Railway 中 provision，并可返回 `GET /api/health` 的 200；仅填写一个未绑定或已删除的 `*.up.railway.app` 域名会导致前端注册、登录显示 Network Error。

#### 3.4 部署
1. 点击「Deploy」
2. 等待构建完成
3. 记录前端 URL，如：`https://vidforge.vercel.app`

---

### 步骤 4：更新跨域配置

#### 4.1 更新后端 CORS 配置
在 Railway 环境变量中更新：

```env
WEB_BASE_URL=https://<你的Vercel域名>
```

#### 4.2 重启后端服务
在 Railway 控制台点击「Redeploy」

---

### 步骤 5：配置自定义域名（可选）

#### 5.1 购买域名
推荐平台：
- 阿里云万网：https://wanwang.aliyun.com
- 腾讯云 DNSPod：https://dnspod.cn
- Namecheap：https://www.namecheap.com

建议选择 `.com` 或 `.cn` 域名，年费约 ¥50-100

#### 5.2 配置前端域名
1. 在 Vercel 项目设置 → Domains
2. 添加你的域名，如 `vidforge.example.com`
3. 按提示在域名服务商处添加 CNAME 记录：

```
类型: CNAME
主机记录: vidforge
记录值: cname.vercel-dns.com
```

#### 5.3 配置后端域名
1. 在 Railway 服务设置 → Domains
2. 添加自定义域名，如 `api.vidforge.example.com`
3. 添加 DNS 记录：

```
类型: CNAME
主机记录: api.vidforge
记录值: <Railway提供的CNAME值>
```

## 五、敏感信息安全管理

### 5.1 核心原则

| 原则 | 说明 |
|------|------|
| **永不提交** | `.env` 文件永远不提交到 Git |
| **最小权限** | 每个密钥只授予必要的权限 |
| **定期轮换** | 建议每 90 天轮换一次密钥 |
| **分级管理** | 开发/测试/生产使用不同密钥 |

### 5.2 本地开发配置

创建本地专用配置文件（不提交到 Git）：

```bash
# 在 apps/backend 目录下
cp .env.example .env.local
```

编辑 `.env.local` 填入真实配置：

```env
# 本地开发配置
DATABASE_URL=postgresql://postgres:password@localhost:5432/vidforge_dev
REDIS_URL=redis://localhost:6379
JWT_SECRET=<本地开发用密钥>

# 火山引擎（使用测试账号或限制配额的密钥）
VOLC_ENGINE_ACCESS_KEY=<开发环境密钥>
VOLC_ENGINE_SECRET_KEY=<开发环境密钥>
```

### 5.3 生产环境配置

**Railway 环境变量管理：**
- 所有敏感配置通过 Railway Dashboard 配置
- 支持引用其他服务的变量（如数据库连接）
- 变更后自动触发重新部署

**Vercel 环境变量管理：**
- 项目设置 → Environment Variables
- 支持 Preview/Development/Production 三套环境
- 敏感变量勾选「Sensitive」选项

### 5.4 密钥存储方案对比

| 方案 | 安全级别 | 适用场景 | 成本 |
|------|----------|----------|------|
| 平台环境变量 | ⭐⭐⭐ | 小型项目、快速部署 | 免费 |
| Vault/1Password | ⭐⭐⭐⭐ | 团队协作、企业级 | $-$$ |
| AWS Secrets Manager | ⭐⭐⭐⭐⭐ | AWS 生态、合规要求 | 按用量计费 |

**推荐**：初期使用平台环境变量，后续可迁移到专业密钥管理服务。

## 九、常见问题排查

### Q1: 前端无法访问后端 API

**检查项：**
1. 后端服务是否正常运行
2. CORS 配置是否包含前端域名
3. 环境变量 `VITE_API_BASE_URL` 是否正确

### Q2: 数据库连接失败

**检查项：**
1. DATABASE_URL 格式是否正确
2. Railway PostgreSQL 是否启动
3. 网络是否可达（Railway 内部网络）

### Q3: 文件上传失败

**检查项：**
1. OSS 配置是否正确
2. Bucket 权限是否为「公共读，私有写」
3. 文件大小是否超限

### Q4: 视频生成任务卡住

**检查项：**
1. Redis 是否正常运行
2. BullMQ Worker 是否启动
3. 火山引擎 API 配额是否充足

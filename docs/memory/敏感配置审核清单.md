# 敏感配置项审核清单

本文档列出所有需要配置的敏感信息，请在部署前逐一审核和配置。

---

## 一、必需配置项（共 11 项）

### 1.1 火山引擎配置（3 项）

| 序号 | 配置项 | 说明 | 获取方式 | 当前状态 |
|------|--------|------|----------|----------|
| 1 | `VOLC_ENGINE_ACCESS_KEY` | 火山引擎访问密钥 | 火山引擎控制台 → 访问控制 → 密钥管理 | ❌ 待配置 |
| 2 | `VOLC_ENGINE_SECRET_KEY` | 火山引擎密钥 | 同上 | ❌ 待配置 |
| 3 | `VOLC_ENGINE_REGION` | 火山引擎区域 | 通常为 `cn-beijing` | ✅ 已有默认值 |

**获取步骤：**
1. 访问 https://console.volcengine.com
2. 完成实名认证
3. 进入「访问控制」→「密钥管理」
4. 点击「创建新密钥」
5. 记录 AccessKeyID 和 SecretAccessKey

---

### 1.2 对象存储配置（4 项）

| 序号 | 配置项 | 说明 | 获取方式 | 当前状态 |
|------|--------|------|----------|----------|
| 4 | `OSS_ACCESS_KEY` | OSS 访问密钥 | 阿里云/火山引擎控制台 | ❌ 待配置 |
| 5 | `OSS_SECRET_KEY` | OSS 密钥 | 同上 | ❌ 待配置 |
| 6 | `OSS_BUCKET` | 存储桶名称 | 创建存储桶时设置 | ✅ 已有默认值 |
| 7 | `OSS_ENDPOINT` | 存储桶端点 | 创建后自动分配 | ✅ 已有默认值 |

**获取步骤（阿里云 OSS）：**
1. 访问 https://oss.console.aliyun.com
2. 创建 Bucket，选择「标准存储」
3. 设置权限为「公共读，私有写」
4. 进入 AccessKey 管理创建密钥
5. 记录 Endpoint（如 `oss-cn-beijing.aliyuncs.com`）

**获取步骤（火山引擎 TOS）：**
1. 访问 https://console.volcengine.com/tos
2. 创建 Bucket
3. 设置权限策略
4. 使用火山引擎同一套 AccessKey

### 1.4 安全配置（2 项）

| 序号 | 配置项 | 说明 | 获取方式 | 当前状态 |
|------|--------|------|----------|----------|
| 10 | `JWT_SECRET` | JWT 加密密钥 | 自行生成强随机字符串 | ❌ 待生成 |
| 11 | `JWT_EXPIRES_IN` | JWT 过期时间 | 通常为 `7d` | ✅ 已有默认值 |

**生成 JWT_SECRET：**
```bash
# 方法 1：使用 Node.js
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"

# 方法 2：使用 OpenSSL
openssl rand -hex 64

# 方法 3：在线生成（不推荐）
# 访问 https://www.grc.com/passwords.htm
```

## 四、安全最佳实践

### 4.1 密钥管理原则

1. **永不提交**：`.env` 文件永远不提交到 Git
2. **最小权限**：每个密钥只授予必要的权限
3. **定期轮换**：建议每 90 天轮换一次密钥
4. **分级管理**：开发/测试/生产使用不同密钥

### 4.2 权限配置建议

| 服务 | 建议权限 |
|------|----------|
| 火山引擎 TTS | 只开通语音合成服务 |
| 火山引擎视频 | 只开通智能创作服务 |
| OSS | 只读写的特定 Bucket |
| PostgreSQL | 应用数据库的读写权限 |

### 4.3 费用控制建议

1. **设置配额告警**：在火山引擎控制台设置费用告警
2. **使用按量付费**：初期使用按量付费，避免预付费浪费
3. **监控用量**：定期查看各服务用量报表

## 五、配置验证

完成配置后，使用以下方式验证：

### 5.1 本地验证

```bash
# 进入后端目录
cd apps/backend

# 复制配置模板
cp .env.example .env

# 编辑 .env 填入真实配置
# 然后启动服务
npm run start:dev

# 访问健康检查
curl http://localhost:3001/api/health
```

### 5.2 生产验证

```bash
# 检查后端健康状态
curl https://<你的后端域名>/api/health

# 预期返回
{"status":"ok","timestamp":"...","uptime":...}
```

选择升级策略

结合"创意工作室风"和功能优先级，以下三种策略各有侧重

A

渐进增强

方式：在现有代码上逐层叠加新功能，先改设计系统主题，再逐个页面升级交互

设计：保留 Ant Design，通过主题覆盖 + CSS 变量实现视觉升级

节奏：快速出效果，但底层架构约束仍在

Pros

  • 最快看到效果
  • 风险最低

Cons

  • 代码质量混合新旧
  • 约束于 Ant Design 框架
稳妥型
B

模块级重构 ⭐

方式：以"页面=功能模块"为单位，每个模块独立重构。保留现有路由壳，逐个重写内部实现

设计：自定义组件体系（创意工作室风）+ 保留 Ant Design 作为基础 UI 库

节奏：可并行开发，每个模块完成后立即可用

Pros

  • 模块间独立，可并行开发
  • 新旧代码边界清晰
  • 每完成一个模块即可上线

Cons

  • 边界管理需注意
  • 前后端联调需同步
均衡型 ⭐ 推荐
C

全量重构

方式：推倒重来，全部用自定义组件系统（TailwindCSS + Radix UI 替代 Ant Design）

设计：完全自定义设计系统，零框架约束

节奏：前期基建时间长，但后期开发体验最佳

Pros

  • 最干净的代码库
  • 设计完全自控
  • 最佳性能

Cons

  • 耗时最长
  • 弃用已有 Ant Design 投资
  • 风险最高
激进型
